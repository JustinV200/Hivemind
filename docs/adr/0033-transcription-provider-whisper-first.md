# ADR-0033: Transcription is one provider protocol on one slot, Whisper first, local first, and audio is never kept by default

- Status: Accepted
- Date: 2026-09-24

## Context

Two callers need speech turned into text: a Worker's ears (the Exoskeleton's `listen` tool, phase
6) and the human's voice at the Hive Entrance (10.5f). Codingrules 8.6 already names the slot
(`ModelSlot.TRANSCRIBER`: audio in, text out, a non-chat slot with its own protocol, metered by the
Fanner and listed on the Forage map) and the adapters it expects (faster-whisper in process, any
server speaking `/v1/audio/transcriptions`, a fake). Every example manifest already binds
`transcriber` to an OpenAI-compatible provider. Open decision 14 asks for the default Whisper size
and whether `faster-whisper` is required. A Night Veil Cell may use only local models, and audio
from a Cell or from the operator is personal data (`C2`).

## Decision

**One protocol, `TranscriptionProvider`,** in `hivemind.llm.transcription`:
`transcribe(clip, language) -> Transcript`, `stream(chunks) -> AsyncIterator[TranscriptSegment]`
for push-to-talk, `capabilities` (streaming, word timestamps, the longest clip it accepts) and
`health()`. `Transcript`, `TranscriptSegment` and `AudioClip` are HiveMind's own frozen models; no
library type leaves an adapter, exactly as for chat (ADR-0008). An adapter without native streaming
buffers the chunks and transcribes once at the end, so every caller can use `stream`.

**Three adapters.** `WhisperLocalTranscription` (`llm/providers/whisper/`) runs faster-whisper in
process: an optional extra (`hivemind[whisper]`), CUDA when present and CPU with int8 otherwise,
inference under `asyncio.to_thread`, one loaded model per instance and so one seat.
`OpenAICompatTranscription` (`llm/providers/openai_compat/transcription.py`) posts multipart to
`/v1/audio/transcriptions` asking for `verbose_json` and accepts a plain `json` reply from servers
that give no segments; the same adapter covers hosted Whisper APIs and local servers.
`FakeTranscription` answers from a script. The vendor-SDK contract gains `faster_whisper`, which
only `llm/providers/whisper/` may import.

**Bound like every other slot.** A new provider kind, `whisper_local`, joins `anthropic`,
`openai_compat` and `fake`; `[llm.slots.transcriber]` names a provider and a model id and may name
a fallback, walked by the same chain rules as chat slots. `ProviderRegistry` builds transcription
providers from their own factory table, lazily and cached, and refuses a kind that cannot
transcribe. Offline mode applies unchanged: `whisper_local` is local by construction, an
OpenAI-compatible one must be loopback or a Virtual Cell gateway.

**Metered by the Fanner.** Every transcription passes a `TranscriptionGate`; the Fanner's
implementation takes a seat from the same per-provider seat meter chat calls use, measures latency
and records one `llm.call` event with the slot, provider, model, the clip's duration in seconds and
the latency, never the audio or the text.

**No default model size in code.** Model ids come from the manifest (codingrules 8.6). The shipped
examples and the docs recommend `large-v3-turbo` where a GPU is present and `small` on CPU until
the eval harness (8.5) measures them; faster-whisper stays optional because it pulls a native
runtime a terminal-only Hive does not need.

**Audio is transient.** A clip exists in memory for the call and, when it came from a Cell, in that
lease's scratch; it is never logged, never on the trail, never in a tool result. The transcript
carries the clearance of its source: `C2` for anything from a Real Cell or the human. The
Entrance's `keep_audio` (10.5f) is the only path that keeps audio, as Nectar with a retention
window. On a Night Veil Cell every slot is local, so this one resolves to a local Whisper.

**Contract suite with fixture clips.** One suite runs over all three adapters: the fake from its
script, the OpenAI-compatible adapter against recorded HTTP exchanges, faster-whisper against a
stand-in model object at the adapter's edge, plus a `local_llm`-marked run against a real model
when one is installed. The fixture clips are short WAV files generated by the test support code,
not recordings of anyone.

## Consequences

Positive: the Entrance's voice route and the Exoskeleton's ears share one implementation and one
slot, and moving that slot from a hosted API to an in-process model is a manifest edit. The Fanner
and Forage map see transcription like any other model use.

Negative: an in-process Whisper holds a model in the Hive Stand's memory (hundreds of megabytes to
a few gigabytes) for as long as the provider is cached. Streaming from a server that has no
streaming endpoint is buffered, so push-to-talk latency is the clip length plus one transcription.

## Alternatives considered

Whisper only through a server: simpler, but a Nuc or a Night Veil Cell would then need a second
process for the one model that runs comfortably in process. Treating transcription as a chat call
with an audio content part: only a few chat models accept audio, and the slot, metering and
fallback rules would bend around a model that is not a chat model. A required dependency: every
terminal-only install would carry a native inference runtime it never loads.
